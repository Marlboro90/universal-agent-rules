# 2. 代码风格

1. **跟随现有风格**：仓库已有约定的，以仓库为准（缩进、命名、引号、分号、导入顺序）。
2. **命名要能自解释**：禁止 `fn p()`、`data2`、`tmp1` 这类名字；名字承担注释的职责。
3. **函数短小、单一职责**：一个函数只做一件事；超过约 40 行考虑拆分。
4. **提前返回，减少嵌套**：用 guard clause 替代多层 `if/else`。
5. **错误处理**：不要吞异常；错误信息要说明「什么失败 + 为什么 + 怎么办」。
6. **注释只写为什么**：解释非直觉的取舍与坑，不重复代码本身能看出来的内容。
7. **不提交调试残留**：`console.log` / `print` / `TODO(临时)` / 注释掉的代码块，提交前清掉。
8. **新增依赖先问**：生产依赖需说明用途与体积影响，优先标准库或已有依赖。
